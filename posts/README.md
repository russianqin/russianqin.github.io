# posts —— 在电脑上写博客

这个目录是博客的「本地写作区」。在这里写 Markdown，推送到 GitHub，
文章就会自动出现在博客上（和以前在 GitHub 网页上新建 Issue 的效果一样）。

（这个 README.md 本身不是文章，不会发布；以下所有说明都不用背，照着抄就行。）

## 发一篇新文章（三步）

1. 在 `posts/` 里复制一份 `_模板.md`，重命名成你想叫的文件名，比如 `莫斯科地铁.md`
2. 用记事本 / VS Code / Typora 打开它，把标题、标签、正文写好
3. 打开 GitHub Desktop → 左下角填一句说明 → Commit to main → Push origin

推送后去 [Actions 页面](https://github.com/russianqin/russianqin.github.io/actions)
能看到正在跑的构建，大约 3 分钟博客就更新好了。

## 文件开头那几行是什么意思

文件最上面被两行 `---` 包起来的部分叫「front matter」，只有两个字段需要你管：

```
---
title: 文章标题
tags: [随笔, 读书]
---
```

- `title`：文章标题（必填，就是博客上显示的标题）
- `tags`：分类标签，可填可不填；多个标签用逗号隔开，也可以写成

  ```
  tags:
    - 随笔
    - 读书
  ```

- 标签不用事先在 GitHub 上建好，脚本会自动创建
- **不要**用这五个名字当标签：`link`、`refreshment`、`quest in Moscow`、`reading`、
  `Curated Articles` —— 它们是现有独立页面的名字，用了会把那些页面顶掉。脚本会拦下来并报错

## 图片

图片分两种写法，可以混着用：

1. **电脑里的图片**：先把图片文件复制进 `posts/images/`，然后在正文里写
   `![说明](images/文件名.png)`。构建时会自动把图片搬到博客里，链接也自动换成
   博客地址（图片永久跟着博客走，不怕原网站删图）
2. **已经在网上的图片**：直接写完整网址 `![](https://...)`，博客会直接引用它

子目录也可以，比如 `posts/images/2026/地铁.png`，正文里写 `![](images/2026/地铁.png)`。
图片文件名用中文没问题；带空格的名字建议写成 `![说明](<images/我的 图.png>)`，
直接写 `![说明](images/我的 图.png)` 也认得出来。

构建时会自动清理 `docs/` 里已经没人引用的旧图，你不用管。

## 改文章、删文章

- **改**：直接改这个 md 文件，再次 commit + push，博客上的那篇会跟着更新
  （文章日期保持第一次发布的那天）
- **删**：把这个 md 文件删掉，commit + push。对应的 GitHub Issue 会被自动关闭，
  博客上这篇就下线了。Issue 和评论都还在，哪天把文件放回来就能恢复
- 想改文件名（重命名 md）等于删掉旧的再新建一篇，请尽量别这么做

## 三条注意

1. **以你电脑上的 md 为准**：如果直接在 GitHub 网页上编辑 Issue 正文，下一次构建会被
   md 的内容覆盖回去。要改内容就改这个 md
2. 单篇文章正文不超过 6 万字（GitHub 单个 Issue 的硬限制），更长的就拆成几篇
3. 文章日期取「第一次发布的时间」，没法手工指定。所以补发多年前的旧文时，
   日期会显示成发布当天
4. 两篇文章不能用同一个标题（博客上会生成同一个网页，脚本会直接报错拦下来）

## 出问题了怎么查

打开 [Actions 页面](https://github.com/russianqin/russianqin.github.io/actions)，
点最新一次运行的 `Generate blog`，里面有每一步的日志。日志里带 `[local]` 开头的是
这个目录相关的信息，比如：

```
[local] 解析到本地文章 1 篇
[local] [新] posts/莫斯科地铁.md → 莫斯科地铁
[local] 完成：新建 1，更新 0，未变 0，关闭 0，清理 0
```

如果某篇被标了「错误」，把那段日志发给我就行。
